## 1. CLAUDE ↔ ADOBE INTEGRATIONS (mid-2026)

### "Adobe for Creativity" connector (the official one)
- Adobe and Anthropic launched the **"Adobe for creativity" connector for Claude** globally on **April 28, 2026**. It's a Claude custom connector (MCP-based) that brings **50+ pro-grade tools** spanning Photoshop, Illustrator, Firefly, Express, Premiere, Lightroom, InDesign, and Adobe Stock directly into Claude's chat interface. **[HIGH]** — [Adobe blog: Adobe for creativity, now in Claude](https://blog.adobe.com/en/publish/2026/04/28/adobe-for-creativity-connector) (2026-04-28); [PetaPixel](https://petapixel.com/2026/04/28/claude-ai-can-orchestrate-creative-workflows-across-adobe-apps/) (2026-04-28)
- **Capabilities**: multi-step orchestration described in natural language — e.g., portrait retouching (balanced lighting, background blur, auto-straighten), social graphics with text/color edits and animation, and **video resizing/reformatting for YouTube Shorts / Instagram Reels**. **[HIGH]** (Adobe blog, same source)
- **Access model**: ~40 tools usable as a **guest with no Adobe account**; signing in with an Adobe ID unlocks more tools, higher limits, and persistent saved work. Using a custom connector at all **requires a paid Claude plan** (Claude Max 20x qualifies). **[MED]** — [usecarly.com: How to Connect Adobe to Claude (and What It Can't Do)](https://www.usecarly.com/blog/claude-adobe-integration/); [Claude Help Center: custom connectors](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)
- **Important limitation**: despite the "Creative Cloud" branding, functional depth is reported to be roughly **Adobe Express-level**, not full desktop-app depth — i.e., it will not replace hands-on Photoshop/Premiere/Lightroom work for anything beyond fairly templated edits. It's also purely reactive (prompted or scheduled), no file-arrival triggers. **[MED]** — [usecarly.com](https://www.usecarly.com/blog/claude-adobe-integration/)
- Output/format: users can download rendered assets directly, or hand off into native Express/Firefly Boards/Creative Cloud apps for further editing. No published pricing beyond "requires paid Claude plan + optional Adobe ID." **[MED]**

### June 2026 "Creative Agent" expansion
- Adobe announced a broader **Creative Agent** expansion (June 2026) covering Firefly (brand kits, product-photo-to-video, storyboard-to-video) plus **Premiere, Photoshop, Illustrator, InDesign, Frame.io in public beta** and **After Effects in private beta**, wired into **ChatGPT, Claude, Copilot, Gemini, and Slack** as front-ends. **[HIGH]** — [Adobe Newsroom: Adobe Unveils Major Expansion of Creative Agent](https://news.adobe.com/news/2026/06/adobe-unveils-major-expansion) (2026-06)

- Adobe's developer-facing **Firefly Services** platform (REST APIs + Node.js SDK) exposes Firefly (generative), **Photoshop API**, **Lightroom API** (being retired, see Q2), and Content Tagging APIs. These require local install (pip/uvx) and manual MCP-host config; treat capability claims from marketplace listing pages as **[LOW]** confidence until tested. **[MED]** — [GitHub: alisaitteke/photoshop-mcp](https://github.com/alisaitteke/photoshop-mcp); [GitHub: mikechambers/adb-mcp](https://github.com/mikechambers/adb-mcp); [mcpmarket.com/server/premiere-pro-automation](https://mcpmarket.com/server/premiere-pro-automation)

Available to Pro/Max/Team/Enterprise at claude.ai/design, included in existing subscription limits (extra usage paid). You can **export from Claude Design directly into Adobe Express** as an editable doc. **[HIGH]** — [Anthropic: Introducing Claude Design](https://www.anthropic.com/news/claude-design-anthropic-labs) (2026-04-17); [TechCrunch](https://techcrunch.com/2026/04/17/anthropic-launches-claude-design-a-new-product-for-creating-quick-visuals/)

**Bottom line for this operator**: the "Adobe for creativity" Claude connector is real, live, and usable today on a Max plan — good for quick thumbnail/social-graphic touch-ups and light Premiere timeline ops — but it is not a substitute for driving the actual Lightroom web editor for the deep, visually-distinctive develop-module edits this content format needs. That's why direct browser automation of lightroom.adobe.com (Q2) remains the core path.

## 2. LIGHTROOM AUTOMATION SURFACE

### lightroom.adobe.com (web) editing capabilities, as of mid-2026
- **Masking**: web Masking tool supports subject/select-sky-style detection plus newly added auto-detection for **mountains, water, vegetation, architecture**, etc. **Quick Actions** now let you zoom in and retouch **individual people** with distinct settings per person. **[HIGH]** — [Adobe: What's new in Lightroom on the web](https://helpx.adobe.com/lightroom/web/whats-new/whats-new-in-lightroom-on-the-web.html)
- **Curves**: a **point curve** tool was added to the web editor (previously desktop/Classic-only), giving real tonal-curve control in-browser. **[HIGH]** (same source)
- **Color Mixer**: web editor gained a **"Color" mode** in Color Mixer plus a Color dropdown, bringing it closer to parity with desktop HSL-style mixing. **[HIGH]** (same source)
- **Presets**: presets sync via Adobe ID across desktop/mobile/web, but there are recent user reports of presets (recommended/premium/own) **not reliably showing up on the web version** even though they work on mobile — treat "presets fully usable in web UI" as **[MED/LOW]**, verify in your own account before scripting around it. — [Adobe Community thread](https://community.adobe.com/questions-680/lightroom-presets-not-available-on-web-version-907971)
- **Versions/snapshots**: web supports **Edit Versions** (Lightroom's version of snapshots) for non-destructive alternates, but I could not find a 2026 doc confirming full snapshot-panel parity with Classic. **[UNVERIFIED]** — treat as needing manual confirmation in-app.
- **Export / max resolution**: this is the critical constraint. Lightroom Web's **"JPEG – Full Size"** export tops out around **4620×3080 px @ 300dpi** (~2MB) with limited customization (no explicit width/height/quality slider comparable to Classic's export dialog). Adobe explicitly recommends the **desktop or mobile app** for high-resolution, print-ready exports — the web app is not designed for that. **[MED]** — [Adobe Community: exporting high resolution edited images from Lightroom web](https://community.adobe.com/questions-680/high-resolution-export-lightroom-online-908455); cross-referenced against general export guides (2026). For a 1080×1920 vertical reel export target this ceiling is a non-issue (far above what's needed), but if you want to screen-capture/reframe from a large source image, web export resolution won't be your bottleneck — the screen-capture resolution (Q5) will be.

### Programmatic / API alternatives to browser automation
- **Lightroom API (Firefly Services)** — being **fully deprecated, End-of-Life July 31, 2026** (i.e., today, per Adobe's own deprecation notice), consolidating into **Photoshop API v2**. Do not build new automation against the standalone Lightroom API. **[HIGH]** — [Adobe: Deprecation Announcements in Lightroom API](https://developer.adobe.com/firefly-services/docs/lightroom/getting-started/deprecation-announcement/)
- **Photoshop API v2** (the replacement, GA) is a unified imaging surface: supports linked smart objects, ICC-profile-aware output (JPEG/PNG/TIFF/PSD), scalable batch/production workflows. Photoshop 2026 desktop also gained **non-destructive Lightroom-style color grading built on Curves**, and curves-on-masks (previously missing). This means the "develop module" feel is migrating into Photoshop rather than being newly exposed via a clean Lightroom-equivalent REST API. **[HIGH]** — [Adobe: Photoshop API v2 — GA](https://developer.adobe.com/firefly-services/docs/photoshop/getting-started/v2-ga/); [Photoshop 2026 features](https://fstoppers.com/photoshop/best-updates-hidden-inside-photoshop-2026-715565)
- **Lightroom Classic SDK (Lua)** — still the only real programmatic hook into "Lightroom-the-develop-tool," but it is fundamentally an **export/publish/metadata/catalog automation SDK**, not a general develop-settings API. It does expose `LrDevelopController` for Quick Develop-level operations (Auto Tone, White Balance, Clipping, and basic Radial/Spot/Graduated filter creation from Library-module-adjacent calls) — but full masking, curves-panel, and Color-Mixer-panel control are **not exposed** as clean, stable API surfaces; several community reports note edge-case bugs (e.g., ICC profile keys on export being ignored). **[MED]** — [developer.adobe.com/lightroom-classic](https://developer.adobe.com/lightroom-classic/); [Adobe Community: SDK/API for Tone Control Auto / White Balance Auto](https://community.adobe.com/questions-675/sdk-or-api-to-run-lightroom-classic-s-tone-control-auto-and-white-balance-auto-982862)
- **Net assessment**: for this project's visual-storytelling use case (showing dramatic before/after develop-module edits on camera), **browser automation of lightroom.adobe.com via Claude-in-Chrome is the most direct and demo-authentic path** — it's literally the UI you want on screen for the reel anyway. The Classic Lua SDK and Photoshop API v2 are better suited to *batch back-office* processing, not to producing the visual "watch Claude edit a photo" footage.

## 3. VIDEO ASSEMBLY PATH (25–60s vertical reels, Windows)

|---|---|---|---|---|
| **ffmpeg** (CLI) | Full — pure CLI/script, filtergraphs for cuts, `atempo`/`setpts` speed-ramps, `subtitles`/`ass`/`drawtext` for burned captions, `-vf scale/crop` to 1080×1920, libx264/NVENC export | Yes, no watermark | Mature, unchanged fundamentals | **Primary recommendation** |
| **Premiere Pro (UXP/ExtendScript)** | Partial | Yes | ExtendScript still works but is **frozen** — "no further changes or improvements... planned," support continues only **through ~September 2026**; UXP is the standard going forward for Premiere 2026, and unlike ExtendScript's synchronous UI-blocking calls, UXP is **async** and doesn't block the UI. **Recommendation**: **ffmpeg-scripted assembly is the most automatable, fully watermark-free path** and requires no additional purchase — it can do cuts (concat demuxer / trim+concat filters), speed ramps (`setpts`/`atempo` or `minterpolate` for smoother ramps), burned-in captions (render an `.ass` subtitle track with karaoke-style highlight, burned via `-vf "ass=captions.ass"`), background music mixing (`amix`/`sidechaincompress` for ducking under narration), and final export to 1080×1920 H.264 (`-c:v libx264` or `-c:v h264_nvenc` if a GPU is present, `-pix_fmt yuv420p` for IG/YT compatibility). This is scriptable end-to-end by Claude Code with zero GUI dependency, unlike Premiere/Resolve/Express which all require either a paid gated API or a live GUI session.

**Fallback**: If timeline-level nonlinear tweaking is wanted with a GUI safety net, **DaVinci Resolve Studio** (one-time purchase, not subscription) is the strongest automatable NLE option — but note this is an *additional cost* beyond the subscriptions already listed, and its scripting API is not available on the Free edition as of 2026.

## 5. SCREEN CAPTURE (deterministic, agent-controllable, Windows)

**Recommended primary path: OBS Studio, remote-controlled via obs-websocket (built into OBS v28+).**

- OBS v28+ ships **obs-websocket** natively — no separate plugin install needed. An automation agent (or a Claude-Code-driven Python/Node script) can connect over `localhost:4455`, authenticate with the configured password, and issue `StartRecord` / `StopRecord` calls (e.g., via the `obsws-python` library: `cl.start_record()`, `cl.stop_record()`). This gives deterministic, scriptable start/stop tied to whatever automation step (e.g., "Claude is about to begin editing in Lightroom") triggers it. **[HIGH]** — [OBS Forums: obs-websocket — Remote-control OBS Studio using WebSockets](https://obsproject.com/forum/threads/obs-websocket-remote-control-obs-studio-using-websockets.58018/page-4); [yostream.io tutorial](https://yostream.io/tutorials/install-obs-websocket-plugin-remote-control-guide/)
- **Concrete settings recommendation**:
  - Capture source: **Window Capture** targeting the Chrome window running lightroom.adobe.com (more stable than full-Display Capture; avoids capturing unrelated desktop elements), or Display Capture if multi-window context is wanted for the reel.
  - Capture resolution: record the **native browser window resolution** (e.g., 1920×1080 or higher if the operator's display is 1440p/4K) at full quality — **do not pre-crop to vertical at capture time**; reframe to 1080×1920 in post via ffmpeg/Resolve, since AI-driven Lightroom UI elements (panels, sliders) are laid out horizontally and you'll want cropping flexibility for reel composition (e.g., picture-in-picture layouts, panel zoom-ins).
  - Frame rate: **30fps** is sufficient for UI/editing capture (cursor and slider movements are not fast-motion content); 60fps is unnecessary overhead unless you plan slow-motion speed-ramps on the screen-capture footage itself, in which case capture at 60fps and speed-ramp down in ffmpeg.
  - Encoder: if an NVIDIA GPU is available, use **NVENC (h264_nvenc)** at a high bitrate (e.g., CQP ~18-20 or a bitrate ≥ 20 Mbps for 1080p) for near-lossless quality with low CPU overhead — OBS's built-in "NVENC" encoder with a quality-focused preset is effectively the GUI equivalent. If capturing via raw ffmpeg instead of OBS, **`ddagrab` (Desktop Duplication API) + `h264_nvenc`** is confirmed to handle high frame rates more reliably than the older **`gdigrab`**, which cannot achieve a true 60fps. **[HIGH]** — [ffmpeg-cookbook.com: FFmpeg Screen Recording](https://ffmpeg-cookbook.com/en/articles/screen-recording/); WebSearch synthesis on gdigrab vs ddagrab performance
  - Record to a high-bitrate intermediate (MP4 or MKV) locally; do NOT record directly at 1080×1920 — always capture landscape/native and reframe in the edit pass, preserving reframing options for dynamic zoom/pan storytelling.
- **How an automated agent starts/stops recording programmatically**: two viable mechanisms —
  1. **obs-websocket** (recommended) — a Python/Node script (invoked as a build step in the content pipeline, or directly by Claude Code via Bash) opens a websocket connection to OBS and calls start/stop; this is fully headless-controllable and needs no UI interaction.
  2. **ffmpeg CLI directly** (`ffmpeg -f ddagrab -framerate 30 -i desktop -c:v h264_nvenc -b:v 20M output.mp4`), launched/killed as a background process by the automation script — simpler (no OBS dependency) but loses OBS's scene-switching/overlay conveniences.
- **Not recommended**: **Xbox Game Bar** — it's a GUI-first, hotkey-driven (Win+Alt+R) consumer tool with **no official CLI/websocket/API for programmatic start-stop**, making it unsuitable for a deterministic, agent-triggered pipeline. **[MED]** (no contrary evidence found of a Game Bar automation API; inferred from absence of any scripting-interface documentation and its design as a manual overlay tool).

## 6. VOICE / NARRATION (TTS for reel voiceovers)

### Paid — ElevenLabs (highest realism)
- Tiers as of 2026: **Free** (10,000 credits/mo, ~10 min TTS, **no commercial rights**) → **Starter ~$5/mo** (30,000 credits, ~30 min, **first tier with commercial license** — the practical minimum for monetized YouTube/IG content) → **Creator ~$22/mo** (121,000 credits) → **Pro ~$99/mo** (500,000 credits) → **Scale ~$299/mo** (2M credits) → **Business ~$990/mo** (6M credits). Annual billing ≈ 17% discount. **[MED]** — [BIGVU: ElevenLabs Pricing 2026](https://bigvu.tv/blog/elevenlabs-pricing-2026-plans-credits-commercial-rights-api-costs/); [texttolab.com: ElevenLabs Pricing 2026](https://texttolab.com/blog/elevenlabs-pricing) (figures vary slightly by source; treat exact numbers as approximate, confirm on elevenlabs.io before committing budget)

- **Google Cloud TTS free tier** (separate from Ultra): 4M chars/month free on Standard/WaveNet voices, 1M chars/month each on Neural2/Studio/**Chirp 3: HD** (Google's newer, ElevenLabs-comparable generative voice line, launched March 2026) — no expiration noted. ### Platform policy on synthetic voiceovers
- **YouTube**: as of the **January 2026** policy update, AI voiceovers/cloned voices/TTS narration fall under the **"altered or synthetic content" disclosure** requirement when content is "meaningfully altered or realistic." Important carve-out: **cloning your own voice for narration does NOT require disclosure**; cloning someone else's voice **does**. Generic TTS narration (not cloning a real identifiable person) for a faceless/tutorial-style channel is generally lower-risk but should still be evaluated against YouTube's exact wording at upload time. **[HIGH]** — [Memeburn: YouTube Now Auto-Labels AI Videos](https://memeburn.com/youtube-now-auto-labels-ai-videos/); [kineclip.com: Is AI Voiceover Safe to Monetize? 2026](https://kineclip.com/blog/is-ai-voiceover-monetizable/)
- **Instagram**: no narration-specific rule found beyond the general AI-content-credentials auto-labeling behavior described in Q4; synthetic voiceover alone (without a cloned real person's identity) is not flagged as a distinct violation category in the sources found. **[MED]**

## RECOMMENDED STACK

| Stage | Primary | Fallback |
|---|---|---|
| **Edit-capture** (recording the Lightroom-in-Chrome session) | **OBS Studio**, remotely started/stopped via **obs-websocket** (built-in since v28) from a Claude-Code-driven script; Window Capture on the Chrome/Lightroom window, native landscape resolution, **30fps**, **NVENC h264** at high bitrate; reframe to 1080×1920 later. | Raw **ffmpeg + `ddagrab`** (`h264_nvenc`) launched/killed as a background process if you want to avoid the OBS dependency entirely. |
| **B-roll generation** | **Gemini Ultra → Flow/Veo 3.1**: native 9:16 generation, image-to-video from up to 3 reference stills, native synced audio, 8s base clips extendable via Scene Extension to ~60s; budget against the 25,000 monthly Ultra credits. **Always tick the platform's AI-disclosure toggle on upload** (SynthID makes silent AI b-roll likely to be auto-detected/labeled anyway). | Adobe Firefly video (image-to-video / Translate video) if Creative Cloud Pro credits are available and Veo output style doesn't fit a shot — otherwise skip, since it draws from the same kind of credit pool and Veo 3.1 is currently the stronger model for native audio + vertical-native generation. |
| **Assembly** (cuts, speed-ramps, 1080×1920 export) | **ffmpeg-scripted assembly** — concat/trim filters for cuts, `setpts`/`atempo` (or `minterpolate`) for speed ramps, `scale`/`crop` to 1080×1920, `libx264`/`h264_nvenc` H.264 export. Fully CLI-automatable, zero watermark, no extra subscription cost. | **DaVinci Resolve Studio** (one-time paid upgrade from Free — note the Free edition's Python/Lua scripting API is Studio-gated as of Resolve 19.1) if timeline-level GUI safety-net editing is wanted alongside scripting. Premiere Pro UXP is a secondary fallback but has real API gaps (e.g., Time Remapping inaccessible from scripting as of 26.3) and ExtendScript is frozen/sunsetting ~Sept 2026. |
| **Captions** (burned-in) | **ffmpeg `subtitles`/`ass` filter** — generate an `.ass` file (word-highlight/karaoke style if desired) from the narration transcript/timestamps and burn in during the same ffmpeg export pass. | Adobe Express's auto-caption tool via the Claude-Adobe connector, accepting its known bug where vertical-resize-after-caption shrinks caption size (do captions after resize, or avoid Express for this step). |
| **Voiceover** | **ElevenLabs Starter tier (~$5/mo)** for commercially-licensed, high-realism narration — cheapest tier that includes commercial rights, ~30 min/month of audio. | **Edge-TTS (free, unlimited)** or **Google Cloud TTS free tier / Chirp 3: HD** (1M-4M chars/month free) as a zero-cost fallback if ElevenLabs credits run out mid-month or budget is paused; disclose AI voiceover per YouTube's Jan-2026 synthetic-content policy regardless of which TTS is used. |
| **Export** | ffmpeg final mux: **1080×1920, H.264 (`libx264`/`h264_nvenc`), `yuv420p`, AAC audio**, targeting IG Reels/YT Shorts spec (25-60s). | Adobe Express export (if the Claude-Adobe connector was used for a quick assembly) accepting its currently-limited export-quality controls as a minor tradeoff. |

**Key risk flags to revisit before building automation around them:**
1. Lightroom API is EOL **today (2026-07-31)** — do not build anything against it; use the web UI directly via Claude-in-Chrome, or Photoshop API v2 for batch back-office work only.
2. DaVinci Resolve **Free** cannot be scripted (Studio-gated since v19.1) — if the plan assumed free-tier Resolve automation, that assumption is false as of 2026.
3. Confirm whether Gemini Ultra's 25,000 credits/month is shared across Veo video **and** Gemini-TTS, or TTS is billed separately — unverified from available sources.
4. Re-confirm Lightroom web presets availability in the operator's own account — community reports suggest inconsistent access as of 2026.
