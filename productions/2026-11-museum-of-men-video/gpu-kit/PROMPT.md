# Task for a Claude Code session on Sparsh's laptop (NVIDIA RTX 3060)

Paste this whole file into Claude Code running on the laptop, opened in the folder that holds
this file and `frames/`.

## Goal
Generate **8 short camera-move video clips** for "The Museum of Men", an Instagram/YouTube/LinkedIn
video for International Men's Day. Each clip starts on one image and ends on another
(first-frame/last-frame conditioning), so it feels like a camera gliding through one gallery.

You make **only these clips**. All text, music, timing and the final edit are done elsewhere
(the Tangent repo, `productions/2026-11-museum-of-men-video/`). Don't add text, music or titles.

## The frames (in `frames/`, 1856×2304, 4:5 portrait, all AI-generated by us, we own them)
- `F0-row.png`: a long row of white plinths in a warm-white gallery; each plinth holds one exhibit (nearest = a drawer of cables).
- `F1-exhibit1.png`: the cable drawer.
- `F2-exhibit2.png`: an empty phone box.
- `F3-exhibit3.png`: a ring of old keys.
- `F4-exhibit4.png`: worn blue rubber chappals.

- `F6-exhibit6.png`: a TV remote in a plastic cover.
- `F7-exhibit7.png`: a phone on a stand, blank light-grey screen.

**STYLE line:** "Calm, premium museum film. Steady gimbal camera, slow eased motion, soft warm
gallery spotlights, no people, no text, no new objects, no flicker, photorealistic."
**Negative prompt (if supported):** "text, letters, logos, people, hands, morphing objects,
melting, flicker, jitter, fast motion, camera shake, blur, distortion".
**Length:** 3-4 s each (whatever the model's natural length is near that). Keep 24 or 30 fps.

## Step 1: check the hardware, and tell Sparsh before installing anything big
- Run `nvidia-smi`. Report the GPU name and **VRAM**. A laptop RTX 3060 usually has **6 GB**; a desktop one has 12 GB.
- Report free disk (models are tens of GB), OS, RAM and Python version.
- Then propose ONE route and get Sparsh's OK before downloading models.

## Step 2: pick a route by VRAM (verify every name, version and licence on the official repo first; don't trust this list blindly)
Candidates as of late 2026, all open-weights with first/last-frame or keyframe conditioning:
- **ComfyUI** (github.com/comfyanonymous/ComfyUI) as the runner, using its official example
  workflows. It handles low-VRAM offloading.
- **~6-8 GB VRAM:**
  - **LTX-Video** (Lightricks; github.com/Lightricks/LTX-Video). Use the smaller or distilled
    checkpoint with keyframe conditioning. Fast; lower fidelity.
  - Or a **quantized (GGUF) Wan** first-last-frame model via ComfyUI-GGUF, if one fits.
- **12 GB+:** Wan 2.x first-last-frame or image-to-video models (github.com/Wan-Video), with
  offloading.
- Confirm each model's licence allows our use (social posts on our own accounts) and note it in the report.

Resolution: generate at the model's supported portrait size closest to 4:5 (e.g. 640×800 or
704×880, multiples of 32). Downscale the frames to that size first; keep 4:5.

## Step 3: generate, review, retry
- 2-3 seeds per clip. Watch each one. Reject:
  - morphing or melting objects;
  - plinths that change count or shape;
  - text appearing;
  - flicker;
  - a last frame that doesn't settle close to the target image.
- **Optional upscale:** Real-ESRGAN (github.com/xinntao/Real-ESRGAN) or a ComfyUI upscaler, 2× → about 1280×1600. Only if it's clean.
- Be honest. If a 6 GB GPU can't produce clean clips, say so and stop. The edit already has a
  non-generative fallback, so nothing is lost.

## Step 4: hand back
- Export the best take of each clip as `C0.mp4` … `C7.mp4`: H.264, no audio, original fps.
- Put them in a `clips/` folder next to this file. Sparsh will upload that folder to the same Google Drive folder.
- Write `REPORT.md`:
  - GPU and VRAM;
  - route, model names, versions and licences;
  - settings (resolution, steps, seeds);
  - time per clip;
  - which clips are good and which are weak, and why.
